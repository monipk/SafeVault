# LifeVault platform setup

The Flutter/Dart source is ready to drop into the user's existing Flutter scaffold. The platform folders generated by `flutter create` remain useful; only a few platform-specific settings need attention.

## Android

Open `android/app/src/main/AndroidManifest.xml`.

Add these permissions inside `<manifest>` if they are not already present:

```xml
<uses-permission android:name="android.permission.USE_BIOMETRIC" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
```

Add these receivers inside `<application>` if they are not already present:

```xml
<receiver
    android:exported="false"
    android:name="com.dexterous.flutterlocalnotifications.ScheduledNotificationReceiver" />
<receiver
    android:exported="false"
    android:name="com.dexterous.flutterlocalnotifications.ScheduledNotificationBootReceiver">
    <intent-filter>
        <action android:name="android.intent.action.BOOT_COMPLETED" />
        <action android:name="android.intent.action.MY_PACKAGE_REPLACED" />
        <action android:name="android.intent.action.QUICKBOOT_POWERON" />
        <action android:name="com.htc.intent.action.QUICKBOOT_POWERON" />
    </intent-filter>
</receiver>
```

The notification implementation uses `inexactAllowWhileIdle`, so the app does not request exact-alarm access.

The current `flutter_local_notifications` documentation notes that scheduled notifications require Android manifest setup and that plugin versions 10+ use core-library desugaring for backwards compatibility. If Gradle reports a desugaring error, enable core library desugaring in your generated Android project using the current plugin documentation for your generated Gradle file format.

## iOS

Open `ios/Runner/Info.plist` and add permission descriptions for the features the app uses:

```xml
<key>NSPhotoLibraryUsageDescription</key>
<string>LifeVault uses your photo library when you attach an image to a document.</string>
<key>NSCameraUsageDescription</key>
<string>LifeVault uses the camera when you attach a document photo.</string>
<key>NSFaceIDUsageDescription</key>
<string>LifeVault uses Face ID to unlock your private information when you enable biometric unlock.</string>
```

The current `image_picker` setup requires the photo-library and camera usage descriptions on iOS, while Android needs no extra image-picker configuration.

## Windows / macOS / Linux / web

The app architecture can compile for these targets, but the MVP is designed around mobile. Notifications, biometric unlock, and local attachments are platform-dependent. The mobile path should be validated first.
